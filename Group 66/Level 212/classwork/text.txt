CSR (Client-Side Rendering)

CSR მიდგომისას სერვერი მომხმარებლის ბრაუზერს უგზავნის თითქმის ცარიელ HTML ფაილს (<div id="root"></div>) და დიდ JavaScript ფაილს. მთლიანი აპლიკაციის რენდერინგი და გვერდის აწყობა ხდება უშუალოდ მომხმარებლის მოწყობილობაზე (კლიენტის მხარეს).

როგორ მუშაობს: ბრაუზერი იღებს ცარიელ HTML-ს, ტვირთავს JS-ს, ასრულებს მას, აგზავნის API მოთხოვნებს (Fetch/Axios) მონაცემების მისაღებად და ბოლოს ასახავს შინაარსს ეკრანზე.

პოპულარული ფრეიმვორკები: React (SPA), Vue, Angular.

უპირატესობები:

სწრაფი ინტერაქცია ჩატვირთვის შემდეგ: გვერდებს შორის გადასვლა ხდება მყისიერად, სერვერის ხელახლა ჩატვირთვის გარეშე (Single Page Application).

ნაკლები დატვირთვა სერვერზე: სერვერი უბრალოდ გასცემს სტატიკურ ფაილებს და API მონაცემებს.

ნაკლოვანებები:

ცუდი SEO: საძიებო სისტემების ბოტები (Google, Bing) ცარიელ HTML-ს ხედავენ და შესაძლოა შინაარსი ვერ დააინდექსო.

ნელი პირველადი ჩატვირთვა (Slow First Contentful Paint): სანამ დიდი JS ფაილი არ ჩამოიტვირთება და არ შესრულდება, მომხმარებელი ხედავს თეთრ ეკრანს ან Spin-ერს.



SSR (Server-Side Rendering)
SSR-ის დროს გვერდის HTML კოდი გენერირდება ყოველი მოთხოვნისას უშუალოდ სერვერზე. სერვერი იღებს მოთხოვნას, ამოაქვს მონაცემები ბაზიდან, აწყობს მზა HTML-ს და უგზავნის ბრაუზერს.

როგორ მუშაობს: მომხმარებელი ითხოვს გვერდს -> სერვერი იღებს მონაცემებს -> სერვერი აწყობს HTML-ს -> ბრაუზერი იღებს მზა HTML-ს და მაშინვე აჩვენებს -> JS იტვირთება და გვერდი ხდება ინტერაქტიული (ეს პროცესი ცნობილია როგორც Hydration).

პოპულარული ფრეიმვორკები: Next.js (React), Nuxt.js (Vue), Remix.

უპირატესობები:

საუკეთესო SEO: საძიებო სისტემები იღებენ სრულად გამზადებულ, შინაარსიან HTML-ს.

სწრაფი პირველადი გამოჩენა: მომხმარებელი ტექსტსა და კონტენტს თითქმის მყისიერად ხედავს.

ნაკლოვანებები:

სერვერის მაღალი დატვირთვა: ყოველ მოთხოვნაზე სერვერს უწევს გვერდის ხელახლა აწყობა.

სერვერის პასუხის დრო (TTFB): თუ ბაზიდან მონაცემების წამოღებას დრო სჭირდება, მომხმარებელი ელოდება სერვერის პასუხს.



SSG (Static Site Generation)
SSG არის მიდგომა, სადაც მთლიანი საიტის HTML გვერდები გენერირდება Build-ის (პროექტის აწყობის) დროს. გვერდები წინასწარ მზადდება და ინახება სტატიკურ ფაილებად (HTML/CSS/JS), რომლებიც შემდეგ ვრცელდება CDN-ის საშუალებით.

როგორ მუშაობს: დეველოპერი უშვებს build ბრძანებას -> ფრეიმვორკი იღებს მონაცემებს და ყველა გვერდისთვის ამზადებს HTML-ს -> მომხმარებლის მოთხოვნისას სერვერი მყისიერად აწვდის წინასწარ გამზადებულ ფაილს.

პოპულარული ფრეიმვორკები: Astro, Gatsby, Next.js (Static Export), Eleventy.

უპირატესობები:

მაქსიმალური სიჩქარე: რადგან ფაილები წინასწარ გამზადებულია და CDN-ზეა განთავსებული, ჩატვირთვა არის ულტრა-სწრაფი.

მაღალი უსაფრთხოება და დაბალი ფასი: არ სჭირდება აქტიური Node.js სერვერი ან მონაცემთა ბაზა ყოველ მოთხოვნაზე, რაც ამცირებს ჰაკერულ რისკებსა და ჰოსტინგის ხარჯებს.

შესანიშნავი SEO.

ნაკლოვანებები:

Build-ის ხანგრძლივი დრო: თუ საიტს აქვს ათასობით გვერდი (მაგ. დიდი ელ-კომერცია), აწყობის პროცესს შეიძლება დიდი დრო დასჭირდეს.

არ გამოდგება ხშირად ცვლადი მონაცემებისთვის: კონტენტის განახლებისთვის საჭიროა ხელახალი Build-ის გაშვება (თუმცა არსებობს ISR - Incremental Static Regeneration მიდგომა ამის შესამსუბუქებლად).
